# 12 错误日志上报

桌面客户端执行失败时，可以把这次的错误日志发给项目维护者，不需要 GitHub 账号。

## 改版说明

马老师专属去广告**不设远程上报服务器**：原版的上报地址是原作者自建的服务，改版不能继续往那送数据。
本版客户端里「上报错误日志」按钮会提示你改走 GitHub Issue，不会把任何内容发到第三方服务器。

## 用户看到什么

1. 完成页出现「有步骤没成功」时，点「上报错误日志」；「反馈问题」窗口里也有这个按钮。
2. 弹出的窗口列出**要发送的全部内容**，原样展示；本版不会真的发出去，窗口会提示你复制诊断内容。
3. 把诊断内容复制到 GitHub 提交 Issue：仓库主页 → Issues → New issue，附上诊断内容即可。

## 诊断包含什么

| 内容 | 说明 |
|---|---|
| 客户端版本、电脑系统 | 比如 `0.2.6`、`Windows 11（AMD64）` |
| 手机品牌、型号、系统版本、Android 版本 | 来自检测页 |
| 各步骤结果 | 步骤名、成功 / 失败 / 跳过、用时 |
| 日志末尾 | 最多 2 万字，和「复制完整诊断」同源 |

复制前客户端会替换：手机序列号 → `<序列号>`，电脑用户目录 → `<用户目录>`，邮箱、11 位手机号、IP 地址 → `<邮箱>` `<手机号>` `<IP>`。

不包含：应用列表、通知内容、账号信息、截图、备份文件。
